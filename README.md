# شنب — موقع الحلاقة والحجوزات

موقع عربي متجاوب ولوحة إدارة للمواعيد والخدمات والأسعار والعروض والفواتير. React + TypeScript، خادم Node.js، وقاعدة SQLite فعلية. الخطوط والصور محفوظة محليًا.

## التشغيل

يتطلب Node.js **24.5 أو أحدث** (تم التحقق على 24.19.0).

```sh
cd /workspace/511
npm ci
npm run dev
```

الخادم على المنفذ `3000`. صفحة العميل `/` ولوحة المالك `/admin`.

للتشغيل بنسخة الإنتاج:

```sh
npm run build
npm start
```

لا يحتاج قاعدة بيانات خارجية. تُنشأ قاعدة `data/shanab.sqlite` تلقائيًا. يمكن تغيير مسارها بمتغير `DATA_FILE` إلى قرص دائم.

## أول دخول للإدارة

1. شغّل الموقع وافتح `/admin`.
2. اقرأ رمز التهيئة من الملف المحلي `data/setup-key.txt` على الخادم. هذا رمز خاص؛ لا تنشره ولا تضفه إلى Git.
3. أدخل الرمز وأنشئ كلمة مرور من 10 أحرف على الأقل. التهيئة متاحة مرة واحدة فقط.
4. بديلًا عن ذلك، عيّن `ADMIN_PASSWORD` بشكل آمن **قبل أول تشغيل**. لا يغير هذا المتغير كلمة مرور حساب تم إنشاؤه سابقًا.

الإدارة محمية بكلمة مرور مشفرة بـ scrypt وجلسة HttpOnly لمدة 12 ساعة. لتصفير كلمة المرور محليًا عند فقدانها، أوقف الخادم، وخذ نسخة احتياطية، ثم نفذ هذا الأمر على جهاز الخادم فقط وأعد التشغيل لتنشئ كلمة مرور بالرمز المحلي:

```sh
node --input-type=module -e "import {DatabaseSync} from 'node:sqlite'; const db=new DatabaseSync(process.env.DATA_FILE||'data/shanab.sqlite'); db.exec(\"DELETE FROM settings WHERE key='admin_hash'; DELETE FROM sessions;\"); db.close();"
```

## الاستخدام

- **العميل:** يختار خدمة أو أكثر، ثم اليوم والوقت والاسم والجوال، ويؤكد الحجز. المواعيد بتوقيت الرياض، لكرسي واحد، كل 15 دقيقة ولمدة 60 يومًا قادمة. يحتسب النظام مدة جميع الخدمات ويمنع التداخل، حتى عند وصول طلبين معًا.
- **المواعيد:** بحث وتصنيف بالتاريخ والحالة، وإلغاء الموعد مع إعادة إتاحة وقته.
- **الخدمات والأسعار:** إضافة وتعديل السعر والمدة والوصف، إخفاء الخدمة بدل حذف سجلها، وترتيبها بالسهمين. الأسعار المبدئية أمثلة قابلة للتعديل وليست أسعارًا مؤكدة للمحل.
- **الفواتير:** من موعد العميل اختر «الفاتورة»، أضف الخدمات المطلوبة، وطبّق خصم مبلغ أو نسبة أو عرضًا محفوظًا. يمكن حفظ مسودة. الإصدار يحفظ الأسعار والخصم نهائيًا، ويحوّل الحجز إلى مكتمل. لا يمكن تعديل الفاتورة بعد الإصدار.
- **العروض:** إعداد عروض مسماة قابلة للتفعيل والإيقاف، تُختار يدويًا لكل فاتورة. العرض لا يتراكم مع الخصم اليدوي؛ يطبّق أحدهما فقط.
- **المشاركة:** رابط خاص عشوائي لكل فاتورة مصدرة، وطباعة/حفظ PDF من المتصفح، وزر واتساب يفتح رسالة مجهزة لجوال العميل. الإرسال اليدوي يحتاج تأكيدك داخل واتساب.
- **الإعدادات:** اسم المحل وساعات العمل ورقم المحل ورابط خرائط Google الذي أرسله المالك. الافتراضي 10 صباحًا إلى 10 مساءً يوميًا ويمكن تعديله. صورة المقعد توضيحية وليست تصويرًا للمحل. رسم الخريطة توضيحي؛ زر الاتجاهات يفتح رابط المحل الفعلي.

الفاتورة إيصال خدمات بدون احتساب ضريبة، وليست نظام فوترة ضريبية إلكترونية معتمدًا. لم يتم إدخال رقم ضريبي أو نسبة ضريبة لعدم توفر معلومات ضريبية للمحل.

## واتساب التلقائي (اختياري، غير مفعل حاليًا)

لا يوجد حساب WhatsApp Business Platform للمحل حتى الآن؛ لذلك يعمل الحجز والفواتير والطباعة والمشاركة اليدوية بدون ربط خارجي. لا توجد رسائل فعلية مرسلة خلال الاختبارات.

عند توفر الحساب:

1. جهّز رقمًا في WhatsApp Business Platform ورمز وصول مخصص للخادم.
2. أنشئ واعتمد قالب **Utility** في WhatsApp Manager بلغتك (`ar` افتراضيًا) ونصًا بأربعة متغيرات في جسمه بالترتيب: **اسم العميل، رقم الفاتورة، الإجمالي بالريال، رابط الفاتورة الكامل**. مثال:
   `مرحبًا {{1}}، شكرًا لزيارتك شنب. فاتورتك رقم {{2}} بإجمالي {{3}} ر.س. تفاصيل الفاتورة: {{4}}`
3. اضبط المتغيرات `WHATSAPP_TOKEN` و`WHATSAPP_PHONE_NUMBER_ID` و`WHATSAPP_TEMPLATE_NAME` و`PUBLIC_URL` عبر إعدادات الاستضافة الآمنة، أو ملف `.env` محلي غير متتبع. يُقرأ `.env` تلقائيًا إن وجد؛ المتغيرات المحقونة مسبقًا لها الأولوية. لا تضع أسرارًا في الواجهة الأمامية.
4. أضف الوجهة `graph.facebook.com` إلى سياسة الشبكة في البيئة السحابية إذا كانت مقيدة، مع إبقاء TLS والوكيل المهيأ مفعّلين. لا تعطل التحقق من الشهادات.
5. أعد تشغيل الخادم. تشير الإدارة إلى أن الربط «مهيأ» عندما تتوفر المتغيرات؛ **ليس هذا إثباتًا لاعتماد القالب أو نجاح الإرسال**. نفّذ اختبارًا مصرحًا به مع جوالك وتحقق من الاستلام قبل استخدامه مع العملاء.

تُضاف الفاتورة لطابور محفوظ في SQLite عند إصدارها، وترسل العامل رسالة القالب خلال نحو 15 ثانية. الإرسال التلقائي للحجوزات التي وافق أصحابها على استخدام البيانات والفاتورة. استجابة المزود تسجّل «قبلها مزود واتساب»؛ لا يدّعي التطبيق تأكيد الوصول، ولا يتتبع حالات delivered/read لعدم إضافة Webhook. تحفظ أخطاء الإرسال مختصرة دون الرموز السرية. الفشل أو انقطاع الخادم أثناء إرسال رسالة يتطلب مراجعة سجل المزود قبل الضغط على إعادة المحاولة، لتجنب إرسال مكرر. الفواتير المصدرة قبل تهيئة الربط تظل متاحة للمشاركة اليدوية ولا ترسل بأثر رجعي.

اختبارات الخادم تستخدم قواعد مؤقتة: منع التداخل، الطلبات المتزامنة، حماية الإدارة والتهيئة، فواتير الخصومات والعروض والأسعار المحفوظة، ترتيب الخدمات، ورسائل واتساب عبر مزود وهمي فقط. اختبارات Playwright تنشئ خادمًا وقاعدة مؤقتة منفصلين وتختبر حجزًا على الجوال وإصدار فاتورة وعرضها، ثم تعديل الخدمات والعروض وساعات العمل. تستعمل Chromium في `/usr/bin/chromium`؛ يمكن تعيين `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` أو تثبيت متصفح Playwright على جهاز آخر. صور التحقق في `test-results/` غير متتبعة.

## الاستضافة والنسخ الاحتياطي

المشروع يحتاج استضافة **Node مستمرة مع قرص دائم**؛ الواجهة وحدها على استضافة ملفات ثابتة لا تكفي للحجوزات. عند النشر، استخدم HTTPS واضبط `COOKIE_SECURE=true` و`PUBLIC_URL` الحقيقي، وأكمل حساب المالك قبل إتاحة الموقع للعملاء. إذا كان هناك وكيل عكسي، حافظ على Host الأصلي حتى يعمل فحص مصدر الطلب. محدد الطلبات يستخدم عنوان الاتصال ولا يثق تلقائيًا برأس X-Forwarded-For؛ جهّز الحماية المناسبة في وكيلك بدل الثقة برأس يرسله العميل.

احتفظ بنسخ احتياطية آمنة خارج قرص التطبيق. لإنتاج نسخة متسقة أثناء التشغيل استخدم SQLite backup API بدل نسخ ملف `.sqlite` منفردًا وهو يعمل في وضع WAL:

```sh
node --input-type=module -e "import {DatabaseSync,backup} from 'node:sqlite'; const db=new DatabaseSync(process.env.DATA_FILE||'data/shanab.sqlite'); await backup(db,'/tmp/shanab-backup.sqlite'); db.close();"
```

انقل النسخة إلى تخزين آمن. تحتوي القاعدة على أسماء العملاء وأرقامهم وفواتيرهم وبيانات دخول الإدارة؛ لا تضعها أو نسخها الاحتياطية في Git أو مجلد `public`. لا تحتاج worktree: استخدم النسخة الحالية في بيئة المهمة المعزولة.
